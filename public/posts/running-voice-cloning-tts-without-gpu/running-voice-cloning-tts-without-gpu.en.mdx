## Running Voice Cloning TTS Without a GPU

I have long been interested in Voice Cloning: creating a new voice from a short reference recording. But when you try to operate it as a service, GPU costs and deployment architecture often become more immediate concerns than model quality.

If every new voice requires retraining a model, GPU jobs and dedicated weights grow with the number of voices. If synthesis also requires a GPU, you either keep that resource running while idle or accept a cold start on every request.

I wanted to approach the problem differently.

`Could I create a voice without a GPU, then keep using it on a small CPU server?`

After several experiments, I built a pipeline that creates Supertonic 3 custom voice JSON on a CPU, registers multiple voices by name on an Oracle Cloud ARM64 server, and uses them for synthesis. I later built a zero-shot Voice Cloning path with Audio8 from the same reference and compared speaker similarity and CPU performance between the two approaches.

## What Is Supertonic TTS?

![Supertonic 3 supports 31 languages and runs on-device using only a CPU](/public/posts/running-voice-cloning-tts-without-gpu/supertonic-3-overview.png)

[Supertonic](https://github.com/supertone-inc/supertonic) is an open-source, on-device multilingual TTS model from Supertone. It is distributed for inference with ONNX Runtime, so it does not require a heavyweight server framework. It can run without a GPU in Python, browsers, and mobile environments.

Supertonic 3, the version used in this article, has roughly 99 million parameters, supports 31 languages, and generates 44.1kHz audio. The official model includes ten voices: five male and five female. What interested me most was not the model size itself, but the separation between the synthesis model and the voice. A single TTS model can produce multiple voices by swapping a small voice style. The [official README](https://github.com/supertone-inc/supertonic#readme) and [Supertonic 3 model card](https://huggingface.co/Supertone/supertonic-3) cover the model specifications and supported environments in more detail.

The official [Python SDK](https://supertone-inc.github.io/supertonic-py/) also includes a local server. After downloading the model, `supertonic serve` starts a CPU-based TTS API, and custom voice JSON files can be loaded into the same runtime. The result is not tied to a specific cloud provider or GPU.

## What Is Audio8 TTS?

[Audio8 TTS](https://github.com/Audio8-AI/Audio8_TTS) is a zero-shot Voice Cloning model that generates new speech while directly conditioning on a reference recording and its transcript. For CPU deployment, I used the published [0.1B ONNX INT8 model](https://huggingface.co/Audio8/audio8-TTS-0.1B-ONNX-INT8).

Its core components are a Neural Audio Codec and a DualAR model. The codec compresses a long waveform into small groups of audio codes. DualAR first produces the broader codes that carry content and timing, then fills in codes for timbre and acoustic detail. Because the reference audio codes are part of the input, the model can follow the original speaker more directly.

The tradeoff is that these codes must be generated in order. This can preserve speaker identity better, but it takes much longer on a CPU than Supertonic's more parallel synthesis path. That architectural difference explains much of the quality and speed gap measured later in this article.

## The Problem Started with the Voice Builder Shutdown Notice

Supertonic once provided Voice Builder, an official tool for creating custom voices. You supplied a short reference recording, generated a voice JSON compatible with your Supertonic version, downloaded it, and loaded it into the local runtime.

On July 23, 2026, however, the [official repository announced the end of service](https://github.com/supertone-inc/supertonic#notice). Official support for the repository ended, and Voice Builder would no longer be accessible after August 31, 2026. Existing JSON files would continue to work, but the official path for creating new voices was no longer a sustainable option.

When a production TTS system depends on a single external web tool to add voices, its voice creation pipeline can stop even while the serving infrastructure remains healthy. That prompted me to look for another way to produce the same kind of artifact as Voice Builder.

## How Supertonic Generates Speech

According to the [SupertonicTTS paper](https://arxiv.org/abs/2503.23108), the model has three main components:

1. A component that compresses speech into a small representation and reconstructs sound from it (speech autoencoder)
2. A generator that turns input characters into that compressed speech representation (flow-matching model)
3. A predictor that decides how long the sentence should take to speak (duration predictor)

In simple terms, Supertonic first decides the speaking duration, creates a compact speech representation of that length, and finally reconstructs the waveform we hear. Keeping the intermediate representation small and processing speech regions together makes synthesis fast even with a compact model.

![Supertonic 3 synthesis pipeline in which character-level text and the style_dp and style_ttl tensors from a voice JSON pass through duration prediction and flow matching to produce a 44.1kHz waveform](/public/posts/running-voice-cloning-tts-without-gpu/supertonic-inference-pipeline.svg)

A custom voice JSON is not a copy of the entire model. The [official SDK guide for custom voices](https://supertone-inc.github.io/supertonic-py/quickstart/) and the [published voice style files](https://huggingface.co/Supertone/supertonic-3/tree/main/voice_styles) show two tensors stored as `data` and `dims`.

```json
{
  "style_dp": {
    "data": ["... 128 floating-point values ..."],
    "dims": [1, 8, 16]
  },
  "style_ttl": {
    "data": ["... 12,800 floating-point values ..."],
    "dims": [1, 50, 256]
  }
}
```

`style_dp` contains 128 values and conditions the duration predictor. `style_ttl` contains 12,800 values and conditions the text-to-latent path. This connection is also visible in the [official Supertonic implementation](https://github.com/supertone-inc/supertonic). The former affects duration and rhythm, while the latter influences timbre and speaking characteristics. Still, they should not be reduced to two independent semantic vectors. The final voice is determined jointly by both tensors, the input text, and the synthesis settings.

From an operational perspective, the process can be divided into two stages:

```text
one-time Voice Cloning
reference audio
  -> voice style search
  -> custom_voice.json

repeated TTS
custom_voice.json + text
  -> Supertonic 3 ONNX runtime
  -> audio
```

If this JSON format can be generated directly, there is no need to copy the ONNX model or run a dedicated server for every voice. The first stage can also be reframed: instead of fine-tuning the entire model, search for a style inside the fixed Supertonic model that resembles the reference.

## I Initially Thought I Had to Train the Model

I first evaluated projects that optimize a Supertonic voice embedding against a reference recording. Some resynthesized the reference transcript and updated the embedding until the result approached the original. Others used speaker encoders such as `ECAPA` or `WavLM` to measure similarity between the two recordings.

The pipelines ran successfully. On Modal GPUs, I preprocessed references, performed hundreds or thousands of optimization steps, and produced JSON files compatible with Supertonic 3.

Listening to the results exposed several problems:

- A male reference sometimes produced a voice that sounded female.
- Speaker similarity scores improved even when the result did not sound much closer to human listeners.
- Some checkpoints moved closer in timbre but introduced more synthetic artifacts.
- In some approaches, the starting point changed depending on the reference language and transcription result.

At first, I assumed more optimization steps would solve the problem. Comparing multiple checkpoints with the same sentence showed that iteration count was not the main issue. What mattered more was which speaker traits the comparison prioritized and which voices Supertonic could express in the first place.

That changed the question.

`Do I really need to retrain the model?`

`Or can I search the voice space already learned by Supertonic for a style close to the reference?`

## Recovering a Voice Style from Speaker Features

The final approach summarizes the speaker traits in the reference, then searches for the closest voice Supertonic can produce.

The process works as follows:

1. Extract the traits that distinguish the speaker in the reference.
2. Build an initial custom voice candidate from those traits.
3. Synthesize a short sentence with that candidate.
4. Compare the result with the reference.
5. Create a better candidate and repeat.

```text
reference audio
  -> summarize speaker traits
  -> create a custom voice candidate
  -> synthesize a short sample with Supertonic
  -> compare with the reference
  -> improve the candidate
  -> custom voice JSON
```

Qwen does not generate the final audio here. It acts as an “ear” that compares the reference with each synthesized candidate. Supertonic 3 generates all production audio from beginning to end.

I used PCA and CMA-ES to generate candidates, but the underlying idea is simple: create several candidate voices with the existing model, synthesize a short sample, compare it with the reference, and keep improving the best candidate. Because the model itself is never retrained, the process can run on a CPU.

The exact transcript of the reference is not required either. A style extracted from a Japanese reference can later synthesize Korean text. Speaker feature extraction and the new text supplied to Supertonic are separate stages.

## Register Once, Then Call the Voice by Name

Even when Voice Cloning runs on a CPU, it does not need to share a server with real-time TTS requests. The two workloads have different lifecycles.

- **Voice Cloning:** Runs once per new voice and uses relatively more CPU and memory.
- **TTS serving:** Loads an existing JSON or voice profile and handles short, repeated requests.

I ran Voice Cloning as a Modal CPU job and downloaded only the resulting JSON or voice profile. The production TTS server runs on an Oracle Cloud Ampere A1 ARM64 instance.

![A one-time Modal CPU Voice Cloning job creates a custom voice JSON, which an Oracle ARM64 server then uses for repeated TTS requests](/public/posts/running-voice-cloning-tts-without-gpu/voice-cloning-serving-split.svg)

The Supertonic server image is based on `python:3.11-slim` and installs only `supertonic==1.3.1` and the ONNX Runtime CPU provider. It does not need CUDA, a PyTorch GPU image, or NVIDIA Container Runtime.

I started with a limit of two CPU cores and 4GB of memory. The model cache and custom voices are stored in separate Docker volumes, while the container root filesystem is read-only. Because the official Supertonic server does not include authentication, I also added ASGI middleware that validates an API key of at least 32 characters.

The completed JSON can be registered through the API without rebuilding the server.

```bash
curl -X POST "https://tts.example.com/v1/styles/import" \
  -H "Authorization: Bearer ${SUPERTONIC_API_KEY}" \
  -F "file=@voices/adam.json"
```

The stem of `adam.json` becomes the voice name, `adam`. Subsequent synthesis requests only need to pass that name.

```bash
curl -X POST "https://tts.example.com/v1/tts" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${SUPERTONIC_API_KEY}" \
  -d '{
    "text": "Hello. This is a custom voice created on a CPU.",
    "voice": "adam",
    "lang": "en",
    "steps": 5,
    "response_format": "wav"
  }' \
  --output adam.wav
```

Registering multiple JSON files makes voices such as `adam` and `airi` available on the same server. To replace an existing custom voice with the same name, add `?overwrite=true` to the import request.

Registered JSON files remain in the named volume mounted at `/var/lib/supertonic/voices`. They are automatically reloaded after a normal image redeploy or container restart, so adding one voice does not require redeploying the server.

I still do not treat the volume as the only backup. A voice JSON may be reproducible, but it represents minutes of search and repeated listening comparisons. I keep an encrypted backup outside the server volume and do not commit voice JSON files to Git.

## Choosing Between Two and Five Steps

Supertonic trades speed for quality through its synthesis step count. I generated the same single line, multiline input, and paragraph at both two and five steps with the same voice.

Two steps responded faster, but synthetic artifacts were more noticeable in long sentences and custom voices. Five steps took longer but produced more stable pronunciation and timbre. I therefore use five steps as the default quality setting in production and consider two steps only for cases such as short previews where latency matters more.

The official documentation does not mandate five steps. SDK examples and defaults vary by environment, so this is an operational choice based on direct listening rather than an official recommendation.

## Comparing Supertonic and Audio8 on Oracle ARM64

After completing the Supertonic pipeline—from voice creation and registration to synthesis settings—I deployed Audio8 0.1B in a separate container on the same Oracle server. Audio8 used four CPU cores and 6GB of memory, while Supertonic used two CPU cores and 4GB. Audio8 ran with `top_k=1` and a precomputed reference cache.

### Comparing Response Speed

I synthesized a single line, multiple lines, and a paragraph with the registered voices. Response time is not limited to inference inside the server. It measures the time from sending a request to the public HTTPS endpoint until the complete WAV arrives, including Cloudflare, network round trips, and WAV encoding.

| Model | Resource limit | Input | Response time | Audio duration | RTF | Speed relative to playback |
|---|---|---|---:|---:|---:|---:|
| Supertonic 3 | 2 CPU cores · 4GB | One line, 27 chars | 3.36s | 4.74s | 0.709 | 1.41× |
| Audio8 0.1B | 4 CPU cores · 6GB | One line, 27 chars | 14.12s | 3.20s | 4.406 | 0.23× |
| Supertonic 3 | 2 CPU cores · 4GB | Multiple lines, 93 chars | 6.98s | 14.07s | 0.496 | 2.02× |
| Audio8 0.1B | 4 CPU cores · 6GB | Multiple lines, 97 chars | 44.56s | 10.68s | 4.171 | 0.24× |
| Supertonic 3 | 2 CPU cores · 4GB | Paragraph, 206 chars | 13.87s | 30.67s | 0.452 | 2.21× |
| Audio8 0.1B | 4 CPU cores · 6GB | Paragraph, 215 chars | 101.32s | 22.76s | 4.452 | 0.22× |

![RTF comparison of Supertonic 3 and Audio8 0.1B for one-line, multi-line, and paragraph inputs on Oracle ARM64](/public/posts/running-voice-cloning-tts-without-gpu/oracle-arm64-benchmark.en.svg)

RTF, or Real-Time Factor, is `response time ÷ generated audio duration`. A value below 1 means generation finishes faster than playback. As the input grew, Supertonic spread fixed costs such as request handling across more audio and improved from an RTF of 0.709 to 0.452. Audio8 stayed around 4.2–4.5 across the three inputs.

The gap comes from how each model generates speech. Supertonic processes speech regions in groups, so its setup cost is spread across longer inputs and its RTF improves. Audio8 must build the audio codes in order, keeping its RTF near 4.2–4.5 even for longer text. The closer voice requires more waiting.

### Which One Fits a CPU Environment?

On a CPU-only system, the right choice depends on the workload.

| Priority | Better fit |
|---|---|
| Fast responses, many requests, small memory footprint | Supertonic 3 |
| Timbre and vocal range closer to the reference | Audio8 0.1B |
| Batch synthesis faster than real time | Supertonic 3 |
| Asynchronous generation where similarity matters more than waiting | Audio8 0.1B |

Neither model wins on every axis. Supertonic behaves like a fast CPU TTS system, while Audio8 trades speed for more direct speaker cloning.

## Supertonic Still Has Quality Limits

This Supertonic architecture removed the GPU requirement, but it cannot reproduce every voice accurately. Supertonic itself does not accept a reference recording as a native Voice Cloning model. Even when the speaker traits are identified correctly, audible differences remain if the base model cannot produce that timbre.

Several problems remained in my tests:

- Unusual delivery and whispered speech produced lower similarity than ordinary speech.
- Some candidates had a vocal range that did not match the speaker's gender.
- Restricting candidates to the neighborhood of real voices still did not eliminate synthetic artifacts.
- Background music, reverberation, or another speaker in the reference quickly degraded the result.

The reference recording mattered more than anything else. The most reliable input was 8–15 seconds of clean speech from one person, with natural delivery, minimal aggressive noise removal, and a speaking style close to the intended use case.

## Closing Thoughts

Listening to outputs created from the same reference made the tradeoff clear. Audio8 followed the speaker more accurately, while Supertonic retained audible differences. That was a natural limitation because Supertonic does not use a reference recording as direct conditioning for native Voice Cloning.

Supertonic, however, generated speech faster than real time on a small CPU. Audio8 spent far more time and memory to produce the closer voice. In a GPU-free CPU environment, I learned that the practical choice is not a single winner, but whether response speed or speaker similarity matters more for the workload.
