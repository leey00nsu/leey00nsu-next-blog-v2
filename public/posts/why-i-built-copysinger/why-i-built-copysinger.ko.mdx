## 사용자별 학습 비용 없이 Voice Cloning을 제품으로 만들기까지

예전부터 TTS와 Voice Cloning 기술에 관심이 많았습니다. 짧은 음성 몇 개로 특정인의 음색을 복제하는 과정이 흥미로웠고, 언젠가 이를 웹 서비스로 만들어보고 싶었습니다.

하지만 구현을 검토하면서 곧바로 비용 장벽에 부딪혔습니다. 당시 검토했던 학습 기반 SVC(Singing Voice Conversion) 방식은 사용자마다 음성 샘플을 모아 전처리하고, GPU에서 별도의 모델을 Fine-tuning한 뒤 전용 `.pth` 가중치를 관리해야 했습니다.

개인 프로젝트 수준에서 사용자 1명마다 전용 학습 파이프라인을 돌리는 것은 GPU 비용과 대기 시간 면에서 지속 불가능했습니다. 만들고 싶었던 건 Voice Cloning '서비스'였지만, 실제로는 모델 학습 인프라 구축에 매몰되는 구조였습니다.

## SoulX-Singer: Zero-shot 모델로의 전환

돌파구가 된 것은 [`SoulX-Singer`](https://github.com/Soul-AILab/SoulX-Singer)였습니다. 이 프로젝트의 SoulX-Singer-SVC는 사용자별 추가 학습 없이, 짧은 레퍼런스 음성 하나만으로 변환할 노래를 레퍼런스의 음색으로 바꾸는 Zero-shot 오픈소스 모델이었습니다.

핵심은 워크플로우의 단순화였습니다. 사용자별 추가 학습 단계가 사라지면서, `사용자 레퍼런스 음성 + 변환할 보컬 음원`만 넣으면 단일 추론(Inference) 파이프라인으로 결과물이 나왔습니다.

![사용자별 데이터 준비와 GPU 학습을 반복하는 학습 기반 SVC와 짧은 레퍼런스로 추론하는 SoulX-Singer-SVC Zero-shot 방식 비교](/public/posts/why-i-built-copysinger/training-vs-zero-shot.ko.webp)

물론 Zero-shot 모델 역시 추론 과정에서 GPU 연산 비용이 들고, 입력 음성의 노이즈나 음질에 민감합니다. 하지만 새로운 목소리를 등록할 때마다 모델을 학습해야 하는 구조적 병목이 사라지면서, 고민의 초점도 학습 인프라 비용에서 실제 사용자가 쓸 만한 UX 설계로 옮겨갈 수 있었습니다.

## 단순 데모에서 제품으로: '곡 선택'의 공백

처음에는 최소한의 파이프라인만 검증하는 단순 데모 화면을 만들었습니다.

1. 원곡에서 보컬/반주 분리
2. 분리된 보컬을 SoulX-Singer-SVC로 사용자 음색 변환
3. 변환된 보컬과 반주를 리믹스

결과 자체는 잘 나왔지만, 데모를 직접 써보며 곧 한계를 느꼈습니다.

* 사용자는 어떤 노래를 골라야 자신의 목소리와 잘 맞는지 알기 어렵습니다.
* 원키가 맞지 않을 때 몇 반음을 올리거나 내려야 할지 판단하기 모호합니다.
* 변환 결과가 어색할 때 이것이 레퍼런스 음질 탓인지, 음역대가 맞지 않아서인지 파악하기 어렵습니다.

단순히 파일 2개를 업로드받아 변환해 주는 기능만으로는 "재미 삼아 한 번 해보고 마는 데모"에 그칠 수밖에 없었습니다.

## 목소리 분석과 곡 카탈로그 매칭

`Copysinger`는 이 선택의 공백을 채우기 위해 기획을 수정했습니다. 무작정 음성을 변환하는 대신, 사용자의 음역대를 먼저 분석하고 가장 어울리는 곡과 추천 키(Key)를 제안한 뒤 믹싱으로 이어지도록 설계했습니다.

![Copysinger 홈 화면](/public/projects/copysinger/copysinger-home.png)

사용자가 브라우저에서 한 소절을 녹음하면, 분석 파이프라인(librosa 기반 pYIN 알고리즘 등)이 다음 지표를 추출합니다.

* **관측 음역 (Pitch Range):** 녹음 중 낸 최저음과 최고음
* **주요 활동 음역 (Core Range):** 유효 음정이 자주 관찰된 구간
* **중심 피치 및 피치 궤적:** 유효 음정의 중앙값과 시간에 따른 음정 변화

![한 소절과 곡 카탈로그를 같은 기준으로 분석해 추천하고 사용자가 선택한 곡만 AI 믹싱으로 연결하는 Copysinger 제품 흐름](/public/posts/why-i-built-copysinger/product-flow.ko.webp)

이때 UI/UX에서 신경 쓴 부분은 "가창력 평가처럼 보이지 않게 하는 것"이었습니다. 한 소절 녹음만으로 사용자의 절대적인 가창력이나 성종을 단정할 수는 없습니다. 그래서 가창력이나 성종을 평가하는 점수는 만들지 않았습니다. 추천 점수는 이번 녹음에서 관찰된 음역과 곡의 음역이 얼마나 맞는지를 나타내는 참고값으로만 사용하고, 몇 반음을 조정하면 더 편한 음역에 들어오는지 함께 보여주도록 구성했습니다.

## 분석용 음성과 합성용 레퍼런스의 전처리 분리

개발 과정에서 마주친 문제 중 하나는, 동일한 녹음 파일을 분석과 합성에 그대로 공유할 수 없다는 점이었습니다. 두 작업이 요구하는 데이터 특성이 상반되었기 때문입니다.

* **보컬 분석:** 음역대 측정을 위해 저음부터 고음까지 사용자가 낸 자연스러운 음성 전체 분포가 필요합니다.
* **SoulX-Singer-SVC 합성:** 레퍼런스가 길다고 품질이 좋아지지 않으며, 오히려 호흡 소리, 무음, 불안정한 음정, 클리핑된 구간이 포함되면 출력물이 왜곡됩니다.

따라서 단일 입력 파일에 대해 전처리 파이프라인을 이원화했습니다.

1. **분석 파이프라인:** 전체 녹음본의 피치 분포를 그대로 보존하여 보컬 프로필 생성
2. **합성 레퍼런스 파이프라인:** 유성 비율, 음량, 클리핑 기준을 만족하는 중음 구간만 골라 시간순으로 연결해 레퍼런스로 전달. 최대 길이는 30초지만, 좋은 구간이 짧으면 반복하거나 다른 음역으로 채우지 않고 확보된 길이만 사용

![하나의 녹음을 전체 피치 분포를 보존하는 분석 경로와 안정적인 중음 구간만 최대 30초로 구성하는 SoulX-Singer-SVC 합성 경로로 분리한 전처리 구조](/public/posts/why-i-built-copysinger/preprocessing-split.ko.webp)

이 분리 작업을 거친 뒤 저음과 고음을 고르게 섞은 레퍼런스보다 안정적인 중음 구간만 사용한 레퍼런스에서 더 깔끔한 합성 결과를 확인했습니다.

## 신뢰성 있는 작업 생명주기: Modal과 PostgreSQL 큐

피치 분석은 수십 초, SVC 추론과 믹싱은 한 곡에 약 3–4분이 걸립니다. 이를 일반적인 단일 HTTP 요청-응답 주기로 처리하면 브라우저 이탈, 네트워크 순단, 서버 재시작 시 작업이 유실됩니다.

이를 해결하기 위해 작업을 비동기 영속 큐 기반으로 분리했습니다.

![웹 요청과 분리된 PostgreSQL 작업 큐, lease 작업자, Modal CPU 분석과 L4 GPU 믹싱, 재접속 가능한 결과 저장 흐름](/public/posts/why-i-built-copysinger/durable-job-flow.ko.webp)

* **상태 관리 및 영속 큐:** 웹 서버는 작업 요청을 접수해 PostgreSQL 큐에 넣고 즉시 작업 ID를 반환합니다. 워커 프로세스가 작업을 가져가 처리하며, 중간에 워커가 비정상 종료되더라도 작업 점유 시간인 lease가 만료되면 다른 워커가 이어받을 수 있게 설계했습니다.
* **컴퓨팅 자원 분리 (Modal):**
  * CPU 집약적인 피치 분석/전처리는 Modal의 CPU 환경에서 실행
  * 무거운 SoulX-Singer-SVC 추론은 Modal의 L4 GPU 환경에서 온디맨드로 실행
  * 사용하지 않을 때 컨테이너를 scale-to-zero하여 GPU 유휴 비용을 줄이고 작업별로 자원을 분리했습니다.
* **스토리지 분리 (Leemage):** DB 용량 부하를 막기 위해 대용량 오디오 원본 및 변환 결과물은 자체 미디어 플랫폼인 [Leemage](https://leemage.leey00nsu.com/)에 보관하고, PostgreSQL에는 메타데이터와 파일 URL 참조만 저장했습니다.

비용도 실제 실행 시간을 기준으로 계산해봤습니다. 2026년 8월 기준 [Modal Starter 플랜](https://modal.com/pricing)은 매달 30달러의 무료 컴퓨팅 크레딧을 제공합니다. L4 GPU는 초당 0.000222달러이고 Copysinger에서 한 곡을 믹싱하는 데 약 3–4분이 걸리므로, GPU 실행 시간만 계산하면 한 곡당 약 0.04–0.053달러입니다. 이론적으로는 무료 크레딧 안에서 한 달에 약 560–750곡을 믹싱할 수 있습니다.

다만 이 수치는 GPU 실행 시간만 반영한 상한입니다. CPU와 메모리 사용량, 콜드 스타트, 작업 완료 후 컨테이너가 잠시 유지되는 시간은 별도로 과금되므로 실제 처리량은 이보다 적습니다. 보컬 분석은 GPU 없이 CPU에서 실행하며, 여섯 차례의 원격 벤치마크에서 분석 1회당 평균 컴퓨팅 비용이 0.001달러 미만이었습니다. GPU 믹싱과 비교하면 전체 비용에 미치는 영향은 작은 편입니다.

결과적으로 사용자가 브라우저 창을 닫더라도 백그라운드에서 작업이 안전하게 완료되며, 나중에 재접속했을 때 완료된 결과물을 바로 확인할 수 있는 환경을 만들었습니다.

## 정리하며

`Copysinger`는 GPU 학습 비용 때문에 묻어두었던 아이디어를 Zero-shot 오픈소스 모델을 통해 실제 서비스로 풀어낸 프로젝트입니다.

모델 자체의 성능도 중요하지만, 사용자가 자연스럽게 사용할 수 있는 입력 전처리, 분석-추천 UX, 그리고 무거운 AI 작업을 웹 요청과 분리해 안정적으로 처리하는 백엔드 생명주기 설계가 뒷받침되어야 비로소 하나의 '제품'이 완성된다는 점을 체감했습니다.
