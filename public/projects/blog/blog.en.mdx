## Project Overview

GitHub : [https://github.com/leey00nsu/leey00nsu-next-blog-v2](https://github.com/leey00nsu/leey00nsu-next-blog-v2)
Demo : [https://blog2.leey00nsu.com](https://blog2.leey00nsu.com)

This is a technology blog I built and operate with Next.js.

I use AI to translate original posts written in Studio and maintain Korean and English documents, then commit them directly to a branch through the GitHub API, automating the flow from writing through translation and commits.

As the content grew and became harder for visitors to navigate, I added a Q&A chatbot that answers using blog posts, profile content, and project documents as evidence.

## Key Features

- **Content authoring and publishing automation**: Connect MDX writing in Studio, AI translation, and GitHub commits
- **Grounded chatbot**: Apply Graph-RAG and citation URL validation to blog posts and project documents
- **Content platform features**: Multilingual MDX, image uploads and optimization, and automatic portfolio PDF generation

## Key Challenges and Solutions

### Repetitive work in multilingual authoring and commits

Writing Korean and English documents separately and committing them manually can lead to missing translations or inconsistent documents. I connected OpenAI translation of Studio content with direct branch commits through the GitHub API, automating writing, translation, and commits as one flow.

### Finding information as content grows

As posts and projects accumulate, visitors have more context to search through themselves. I introduced an AI-powered chatbot that searches blog posts, profile content, and project documents to answer their questions. I combined lexical and curated search with PostgreSQL (pgvector) Graph-RAG and used a question router to choose retrieval paths based on the question type. I checked that citation URLs belonged to the search results and withheld generated answers without validated sources.

### Image-related rendering performance issues

Rendering images without knowing their dimensions or placeholder data can cause layout shifts and initial image loading issues. I pre-generated width, height, and LQIP metadata for uploaded images and used it during rendering.
