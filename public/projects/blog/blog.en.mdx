## Project Overview

GitHub : [https://github.com/leey00nsu/leey00nsu-next-blog-v2](https://github.com/leey00nsu/leey00nsu-next-blog-v2)
Demo : [https://blog2.leey00nsu.com](https://blog2.leey00nsu.com)

This is a technology blog I built and operate with Next.js.

I use AI to translate original posts written in Studio and maintain Korean and English documents, then commit them directly to a branch through the GitHub API, automating the flow from writing through translation and commits.

As the content grew and became harder for visitors to navigate, I added a Q&A chatbot. It searches blog posts, profile content, and project documents to answer questions and uses the context of earlier turns to handle follow-up questions.

## Key Features

- **Content authoring and publishing automation**: Connect MDX writing in Studio, AI translation, and GitHub commits
- **Grounded chatbot**: Search blog posts, profile content, and project documents using the question and conversation context, with citations to public documents used in the answer
- **Content platform features**: Multilingual MDX, image uploads and optimization, and automatic portfolio PDF generation

## Key Challenges and Solutions

### Repetitive work in multilingual authoring and commits

Writing Korean and English documents separately and committing them manually can lead to missing translations or inconsistent documents. I connected OpenAI translation of Studio content with direct branch commits through the GitHub API, automating writing, translation, and commits as one flow.

### Finding information as content grows

As posts and projects accumulate, visitors need to read through more documents to find what they need. I built the chatbot so they can ask for information and follow up on earlier answers.

I adopted TypeSafe Jev to identify the intent of a question quickly before retrieval and answer generation. With reported response times as low as [70ms](https://typesafe.ai/blog/introducing-system-one-models-and-jev?render=full), Jev interprets the question and conversation context together to determine the search targets, scope, and time constraints.

I combine keyword search, curated profile and project sources, and PostgreSQL (pgvector) Graph-RAG, with LangGraph managing the flow from question interpretation through retrieval, answering, and validation.

Greetings and requests for public contact details use prepared responses. Questions that need explanations are answered using retrieved evidence. The server checks the evidence IDs selected by the model against the search results and provides citations to public documents. If evidence is insufficient or validation fails, the chatbot explains that it cannot answer.

### Image-related rendering performance issues

Rendering images without knowing their dimensions or placeholder data can cause layout shifts and initial image loading issues. I pre-generated width, height, and LQIP metadata for uploaded images and used it during rendering.
