## 프로젝트 소개

GitHub : [https://github.com/leey00nsu/leey00nsu-next-blog-v2](https://github.com/leey00nsu/leey00nsu-next-blog-v2)
Demo : [https://blog2.leey00nsu.com](https://blog2.leey00nsu.com)

Next.js 기반으로 직접 운영하는 기술 블로그입니다.

자체 Studio에서 작성한 원문을 AI로 번역해 한국어·영어 문서를 관리하고, GitHub API를 통해 브랜치에 직접 커밋해 작성·번역·커밋까지 이어지는 흐름을 자동화했습니다.

이후 콘텐츠가 늘어나면서 방문자가 원하는 정보를 찾기 어려워져 Q&A 챗봇을 추가했습니다. 블로그 글, 소개, 프로젝트 문서를 검색해 답변하고, 앞선 대화의 문맥을 반영해 후속 질문에도 이어서 답할 수 있도록 구성했습니다.

## 주요 기능

- **콘텐츠 작성·게시 자동화**: Studio에서 MDX 작성, AI 번역, GitHub 커밋까지 연결
- **근거 기반 챗봇**: 질문과 이전 대화의 문맥을 반영해 블로그 글·소개·프로젝트 문서를 검색하고, 답변에 사용한 공개 문서의 출처 제공
- **콘텐츠 플랫폼 기능**: 다국어 MDX, 이미지 업로드·최적화 및 포트폴리오 PDF 자동 생성

## 핵심 문제와 해결

### 다국어 콘텐츠 작성과 커밋의 반복 작업

한국어와 영어 문서를 별도로 작성하고 직접 커밋하면 번역 누락이나 문서 불일치가 발생하기 쉽습니다. Studio에서 작성한 콘텐츠를 OpenAI로 번역하고 GitHub API를 통해 브랜치에 직접 커밋하도록 연결해 작성·번역·커밋 흐름을 하나의 과정으로 자동화했습니다.

### 콘텐츠가 늘어날수록 어려워지는 정보 탐색

글과 프로젝트가 늘어나면 방문자가 필요한 내용을 찾기 위해 여러 문서를 살펴봐야 합니다. 챗봇에서 질문으로 정보를 찾고, 앞선 답변에 대해 이어서 물어볼 수 있도록 했습니다.

검색과 답변 생성에 앞서 질문의 의도를 빠르게 파악하기 위해 TypeSafe Jev를 도입했습니다. 빠르면 [70ms 수준](https://typesafe.ai/blog/introducing-system-one-models-and-jev?render=full)으로 응답하는 Jev를 활용해 질문과 이전 대화의 문맥을 함께 해석하고, 검색 대상과 범위, 기간 조건을 정하도록 구성했습니다.

키워드 검색과 소개·프로젝트 문서 검색, PostgreSQL(pgvector) 기반 Graph-RAG를 조합하고, LangGraph로 질문 해석부터 검색·답변·검증까지의 흐름을 관리합니다.

인사나 공개 연락처처럼 준비된 정보로 답할 수 있는 질문은 직접 처리합니다. 설명이 필요한 질문은 검색한 근거를 바탕으로 답변하고, 모델이 선택한 근거 ID를 검색 결과와 대조해 공개 문서의 출처를 제공합니다. 근거가 부족하거나 검증에 실패하면 답변하기 어렵다는 안내를 반환합니다.

### 이미지로 인한 렌더링 성능 저하

이미지의 크기와 Placeholder 정보를 알 수 없는 상태로 렌더링하면 레이아웃 이동과 초기 이미지 로딩 성능 문제가 발생할 수 있습니다. 업로드된 이미지의 width·height·LQIP 메타데이터를 사전에 생성하고 이를 렌더링에 활용하도록 구성했습니다.
