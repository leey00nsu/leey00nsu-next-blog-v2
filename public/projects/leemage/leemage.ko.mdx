## 프로젝트 소개

GitHub : [https://github.com/leey00nsu/leemage](https://github.com/leey00nsu/leemage)
Demo : [https://leemage.leey00nsu.com/](https://leemage.leey00nsu.com/)

사이드 프로젝트에 파일 업로드 기능을 추가하면서 스토리지 비용 문제가 발생해, OCI Object Storage와 Cloudflare R2의 Free Tier를 활용하는 자체 파일 관리 플랫폼을 구축했습니다.

프로젝트 단위로 이미지·비디오·문서 등의 파일을 관리하고, REST API와 TypeScript SDK를 통해 다른 프로젝트에서도 동일한 업로드 기능을 쉽게 사용할 수 있도록 구성했습니다.

또한 특정 스토리지에 종속되지 않도록 공통 인터페이스를 설계하고, 이미지 변환과 최적화 기능까지 함께 제공하도록 확장했습니다.

## 주요 기능

- **파일 관리**: 프로젝트 단위로 이미지·비디오·문서 등 다양한 파일 업로드 및 관리
- **이미지 처리**: 이미지 리사이즈 및 WebP·AVIF 등의 포맷 변환
- **외부 연동**: REST API와 TypeScript SDK, OCI Object Storage·Cloudflare R2 지원

## 핵심 문제와 해결

### 대용량 파일 업로드로 인한 서버 부하

파일을 애플리케이션 서버를 통해 전달하면 파일 크기에 따라 서버의 메모리와 네트워크 부하가 증가합니다. Presigned URL을 이용해 최초 업로드 본문은 클라이언트에서 Object Storage로 직접 전송하고, 서버는 업로드 확인과 파일 등록을 담당하도록 분리했습니다. 이미지 검증과 변환이 필요한 경우에는 서버에서 원본을 읽어 처리합니다.

### 스토리지마다 다른 API 인터페이스

OCI Object Storage와 Cloudflare R2는 서로 다른 API 인터페이스를 사용하기 때문에 스토리지를 변경하면 서비스 코드까지 수정해야 할 수 있습니다. 공통 Storage 인터페이스와 Adapter 패턴을 적용해 서비스 로직과 프로바이더 구현을 분리하고, 동일한 파일 관리 흐름에서 OCI와 R2를 선택해 사용할 수 있도록 했습니다.

### 이미지 용량과 변환 비용

원본 이미지를 그대로 저장·전송하면 파일 용량이 커지고 네트워크 비용도 증가합니다. Sharp를 이용해 요청한 크기·포맷의 파생 이미지와 썸네일을 순차 생성하고, 원본과 파생본의 URL·크기·포맷을 함께 관리하도록 했습니다.
