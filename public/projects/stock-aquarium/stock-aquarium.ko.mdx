## 프로젝트 소개

GitHub : [https://github.com/leey00nsu/stock-aquarium](https://github.com/leey00nsu/stock-aquarium)<br />
Demo : [https://aquarium.leey00nsu.com/](https://aquarium.leey00nsu.com/)

한국투자증권(KIS)의 실시간 주식 체결 데이터를 **3D 수조 속 물고기 움직임으로 변환한 데이터 시각화 서비스**입니다. 매수 체결은 오른쪽으로 이동하는 빨간 물고기, 매도 체결은 왼쪽으로 이동하는 파란 물고기로 표현하고 체결량에 따라 크기를 조절합니다.

숫자와 차트 중심의 시세 화면 대신 시장의 방향, 체결 강도, 거래량과 변동성을 하나의 수중 환경으로 보여주는 것이 목적입니다. 거래량이 늘면 물고기와 입자가 빨라지고, 변동성이 커지면 수조에 폭풍과 카메라 흔들림이 발생합니다.

## 핵심 기능

- 매수·매도 체결 방향과 규모를 물고기의 이동 방향, 색상, 크기로 시각화
- 거래량 급증, 변동성 확대와 거래정지를 수중 환경 변화로 표현
- 국내·미국 주요 40개 종목 검색과 실시간 현재가 조회
- 단일 KIS WebSocket 연결을 여러 브라우저에 SSE로 팬아웃
- 100ms 단위 체결 집계와 250ms 단위 물고기 생성량 제어
- 80개 고정 객체 풀과 단일 프레임 루프를 사용한 3D 렌더링
- 서버 메모리·디스크를 조합한 종목 마스터 이중 캐시
- 목 시세 모드와 실제 KIS 실전·모의투자 데이터 전환

## Problem

- **고빈도 체결 데이터**: 순간적으로 많은 체결이 들어오면 브라우저마다 WebSocket을 열거나 이벤트마다 3D 객체를 생성하는 방식은 서버와 렌더링 부하가 큼
- **종목별 유동성 차이**: 절대 체결량만 사용하면 거래량이 큰 종목과 작은 종목의 물고기 크기를 같은 기준으로 비교하기 어려움
- **실시간 연결 공유**: 같은 종목을 보는 사용자가 늘어날 때 KIS 구독과 JSON 직렬화를 사용자 수만큼 반복하지 않아야 함
- **3D 객체 수명 관리**: 물고기 모델, 스켈레톤 애니메이션과 이동 상태를 계속 생성·제거하면 프레임 드롭과 메모리 부담이 발생
- **운영 보안과 복구**: KIS 자격 증명을 브라우저에 노출하지 않으면서 연결 제한, 재연결과 종목 데이터 장애에 대응해야 함

## Solution

- **서버 전용 KIS 게이트웨이**: KIS App Key와 Secret은 서버에서만 사용하고, 하나의 WebSocket 연결에서 받은 체결을 Next.js Route Handler의 SSE로 재배포
- **종목 단위 팬아웃**: 체결 데이터의 집계와 JSON 직렬화를 종목별로 한 번만 수행하고 동일 종목을 구독한 모든 브라우저가 같은 SSE 바이트를 공유
- **상대적 체결량 계산**: 종목별 최근 40개 체결량의 백분위로 물고기 크기를 0.6~2.5배 범위에 매핑하여 유동성이 다른 종목도 일관된 크기로 표현
- **고정 객체 풀**: 시작 시 80개의 물고기를 준비해 재사용하고, 한도를 넘는 체결은 버리지 않고 방향별 수량과 횟수로 합산해 다음 객체에 반영
- **연결 보호와 자동 복구**: 전체·IP별 연결 및 재시도 제한을 적용하고, KIS 연결이 끊기면 지수 백오프로 재연결한 뒤 사용 중인 종목만 다시 구독
- **이중 캐시와 폴백**: 종목 마스터를 서버 메모리에 24시간 보관하고 디스크 캐시를 함께 사용하며, 미국 순위 조회가 실패하면 내장 대표 종목 목록으로 시작

## Impact

- **실시간 데이터의 직관적 표현**: 매수·매도 방향, 체결 규모와 시장 변화를 숫자를 읽지 않아도 수조의 움직임으로 파악 가능
- **구독 자원 절감**: 같은 종목을 100명이 보더라도 서버의 KIS 실시간 구독은 한 건만 유지하도록 구성
- **안정적인 렌더링 상한**: 최대 80개의 물고기를 재사용해 체결량이 급증해도 무제한으로 3D 객체가 늘어나지 않도록 제한
- **데이터 유실 완화**: 생성 속도를 넘는 체결을 방향별로 합산하여 시각적 이벤트 수는 줄이되 체결량 정보는 다음 물고기에 반영
- **운영 가능한 실시간 서비스**: 재연결, keep-alive, 요청 제한, 보안 헤더와 캐시 폴백을 포함해 장시간 연결을 전제로 한 운영 기반 구축
